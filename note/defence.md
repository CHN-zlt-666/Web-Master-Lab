# 防御方式

- sql注入

  核心思想：让用户无法对sql语句进行拼接操作
  1. 预处理
  2. 类型转换。在某些特殊环境下只能输入某种类型
  3. 其他操作：白名单，减少错误提示

- xss

  核心思想：不让用户输入的内容被当作HTML或者JavaScript代码解析
  1. htmlspecialchars函数进行转义
  2. 对输入进行校验。不允许<>"'&等特殊字符输入
  3. HttpOnly限制cookie读取

- csrf

  核心思想：对发送的请求加强身份验证
  1. token防御
  2. samesite限制跨站时发送cookie
  3. referer和origin检查
  4. 防御xss（xss可以打穿浏览器拿到token）

- 文件上传

  核心思想：限制php代码的上传，限制文件被php解析器处理
  1. 白名单限制后缀
  2. 图片进行二次渲染
  3. 验证文件内容，验证文件头
  4. 服务器配置对php解析器的限制
  5. 上传目录与Web分隔，只能通过程序间接访问

- 文件包含

  核心思想：限制函数参数以及php解析器对文件的解析
  1. 白名单限制文件包含函数的参数
  2. 限制目录穿越
  3. 关闭部分危险伪协议
  4. 随机重命名

- 命令注入

  核心思想：限制用户无法控制最终执行命令
  1. 限制空格，使多个命令无法被解析。（但方案存在绕过）
  2. 白名单与黑名单限制输入

- 反序列化

  核心思想：不要反序列化用户的可控数据，同时要限制魔术方法与危险函数的联系
  1. 不反序列化用户的输入
  2. 使用JSON格式存放对象
  3. 在魔术方法中不要存放危险函数

- xxe

  核心思想：限制XML数据定义，限制服务器访问外部资源
  1. 限制服务器对外部资源的访问
  2. 限制实体DTD的定义
  3. 禁用外部实体

- ssrf

  核心思想：限制通过url直接访问服务器本地的操作
  1. 白名单和黑名单限制url
  2. 拦截内网ip
  3. 限制危险协议：伪协议等

- jwt

  核心思想：加强密钥的私密性
  1. 使用强密钥
  2. 对生成的jwt加生命周期
  3. 固定算法。拒绝none

- 越权：

  核心思想：检验用户身份是否与访问资源所属者一致
  1. session，jwt进行垂直越权防御
  2. 通过jwt中存放的id与访问的id进行对比

- 防御的核心不在单点防御，攻击者总能进行绕过，关键点在于断开攻击链，如：文件上传。并且真实场景下的攻击从来不是单点打破，而是不同的漏洞进行串联，形成的攻击链
