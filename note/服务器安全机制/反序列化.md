- 序列化是什么？

  程序中的对象不能一直存在，序列化的作用就是将对象转化为字符串，达到对象长期存在的效果

- 反序列化漏洞产生的前提：程序相信了攻击者所提供的序列化数据，恢复出了攻击者所构造的对象

# 魔术方法：

- 魔术方法是一种在特定条件下自动触发的方法
- 常用以下方法：
  1. \_\_construct( ) 在对象创建时自动调用
  2. \_\_destruct( ) 在对象生命周期结束时调用
  3. \_\_wakeup( ) 反序列化恢复对象时调用
- 在反序列化中真正有危害的并不是函数本身，而是开发者在魔术方法里面进行调用了其他危险函数

# pop链：

- pop链是类的相互依赖关系所产生的，类似于在java等编程语言里面面向对象中的类互相调用方法
- 大致流程： 魔术方法->普通函数->...->普通函数->危险函数
- 但pop链不是漏洞，而是一种攻击路径。真正的漏洞是程序把攻击者可控的数据交给了unserilaize( )
- pop链困惑点：开发者定义了类中的变量，为什么攻击者能够修改类的依赖关系？

  攻击者并没有对php进行修改，并且攻击者是无法触碰php代码的，关键点在于攻击者通过构造字符串在进行反序列化时，修改了对象的属性，例如：

  ```php
  class A {

  public $b;

  public function __destruct() {
      $this->b->hello();
  }

  }
  ```

  这里的$b是类A的一个属性，并没有被限制为某个特定的属性，而攻击者就是找到这些属性的联系进行攻击。（在该例子中就需要下一个有联系的类中存在hello函数）

- pop难点在于，攻击者需要在成百上千的类中找到这些属性的联系，根据函数名进行联系的查找，最后形成pop链
- pop链会导致许多漏洞产生，关键点在于pop链最终到达的危险函数，危险函数决定了最终会导致的漏洞，例如：删除文件，lfi

# 反序列化产生的两个核心条件：

1. 用户可控unserilaize( ) 函数的输入
2. 存在一条能够从魔术方法到危险操作的执行路径（复杂的为pop链，简短的可以直接由魔术方法调用危险函数的路径）

- 序列化得到的字符串包含了对象之间的引用关系，同时也包含了对象的属性，而属性可能在函数里面当作变量赋值给危险函数，所以说这一步就是控制危险函数再进行危险操作

# 靶场实验内容：

1. 通过序列化和反序列化函数验证了字符串可以恢复对象的内容，**并且恢复了对象之间的方法引用**

   （但反序列化得到的对象不能直接通过echo输出）

2. 对象替换：将类1中未命名的变量进行替换为另一个对象类3（应该为类2），但类3必须要有类1引用类2的函数。见靶场中类A，B，test的关系
3. 对象属性和函数参数不是一个东西，在faker类的危险函数中可见，直接传属性即可，不需要传参，这也就是控制了危险函数的参数（第47行可见）
4. 序列化得到的字符串有一定的规律和格式
5. 反序列化攻击的是对象的属性而不是代码，属性值一路传递到危险函数的参数，控制了危险操作
6. 后续添加了wakeup和toString的魔术方法进行构建不同的pop链
   **echo 一个对象时，会自动调用这个对象的 toString() 方法，并 echo 它的返回值。**
