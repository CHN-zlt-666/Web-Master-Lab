# 基础知识补充

- 对于php的补充：php是连接web和OS之间的一个桥梁，同时php本身就是在操作系统上面的进程，并不是只能被限制在网页内
- php进行控制OS的流程：php并不能直接对OS进行控制，而是通过接口间接进行操控OS
- 完整结构链：
  ```php
  [服务器（机器）]
    ↓
  [操作系统（Linux / Windows）]
    ↓
  [Web服务器（Apache / Nginx）]
    ↓
  [后端程序（PHP / Node / Java）]
    ↓
  [数据库 / 文件系统]
  ```

# 命令注入

- 命令注入的本质：web应用将用户输入传给shell，而shell作为操作系统接口执行命令，让攻击者间接的进行控制操作系统
- 危险函数：
  1. system: 直接执行命令，并且输出结果到页面
  2. exec：执行命令，默认不输出结果，将结果存放到数组/变量
  3. shell_exec：返回完整字符串结果（常用于回显型漏洞）
  4. passthru：直接输出原始系统结果（常用于二进制命令）

# shell解释器

- 解析规则：shell先将输入的字符串进行词法解析拆词，再进行语法解析判断结构后进行命令执行
- 分隔符（语法规则）
  - ; 进行分割多个命令
  - $ 标准分隔符
  - && 前面部分执行成功后才执行后面
  - || 前面部分执行失败才执行后面
- 命令替换: $(cmd)或者`cmd`进行操作，作用是先执行内层命令，后替换外层。如:
  ```php
  echo whoami;
  echo $(whoami);
  ```
  第一行输出 whoami,第二行输出asus

## 防御与绕过操作：

1. 经典空格防御与绕过：
   - 防御思想：通过限制空格，让shell解释器无法识别后续的操作，本质和ping拼接问题一致
   - 绕过思想：让shell解释器把某种字符解释为空格即可
   - （更多是针对于Linux系统的shell解释器，Windows无法处理，所以目前还未进行测试绕过）

2. 黑名单防御：
   - 防御思想：将分隔符进行黑名单操作，使后续的命令无法执行
   - 缺陷：黑名单只限制了某几种开发者想得到的防御方式，无法彻底防御千奇百怪的绕过技巧，所以白名单防御机制是更为全面的

3. 白名单防御：
   - 防御思想：只允许某几种安全命令通过，比黑名单更安全

---

**总结**

- 命令注入本质：攻击者能够控制命令执行函数的命令内容，使shell将攻击者构造的命令交给操作系统执行，从而实现任意命令执行
- 防御方式：让用户无法控制最终的执行命令
- （命名注入和sql有点类似，都是利用的字符串的拼接进行后续漏洞产生与攻击）
